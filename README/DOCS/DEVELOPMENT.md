## Design rules

1. **Determinism is a feature.** All random draws happen on the calling thread. Evaluation is the only thing sent to Rayon, and results return in input order. A test compares a one thread pool with a four thread pool and requires identical output.
2. **No hidden state.** Bounds live in the problem, caches are per instance, and no global mutable state exists. This is why a benchmark can be built twice and compared.
3. **The traits stay small.** A problem supplies its dimension, bounds, objective count, constraint count and one evaluate function. Everything else has a default.
4. **Scores own their numbers.** `Score` stores objectives, constraints and the derived violation, so selection never recomputes a constraint.
5. **Numbers that matter are named.** Defaults are public constants such as `de::DEFAULT_BUDGET_PER_DIM` and `moead::DEFAULT_BUDGET`, and the documentation quotes them.
6. **A failed fit is not a panic.** Ridge returns `Option`, and the search treats `None` as a large error.
7. **No unsafe code.** There is none in the crate.

## Dependencies

Four crates, each doing one job: `rayon` for the evaluation batch, `clap` for the command line, `serde` and `serde_json` for JSON Lines input and the report output. The random generator, the linear algebra and the optimisers are in the crate.

`argmin` was considered for the solvers and is not used. It is a good framework, but it ships CMA-ES, particle swarm, simulated annealing and gradient methods, not SHADE, jDE or MOEA/D, so it would replace none of the algorithm code. It would add a solver type parameter and a second problem abstraction on top of a trait that is already six methods. The parallel evaluation here is also part of the reproducibility contract, which is easier to guarantee directly than through a generic backend.

## Adding a problem

Implement `Problem` and pass it to either engine. Constraints are optional and follow `g <= 0`.

```rust
use xcm_mmm::problem::{Bounds, Problem};

struct AckleyLike {
    bounds: Bounds,
}

impl Problem for AckleyLike {
    fn name(&self) -> &str {
        "ackley-like"
    }

    fn dim(&self) -> usize {
        self.bounds.dim()
    }

    fn bounds(&self) -> &Bounds {
        &self.bounds
    }

    fn evaluate(&self, x: &[f64], f: &mut [f64], _g: &mut [f64]) {
        f[0] = x.iter().map(|v| v * v).sum::<f64>().sqrt();
    }
}
```

The implementation must be `Sync` and pure. Purity is not enforced by the compiler, but a problem that returns different values for the same point breaks reproducibility and invalidates the memory of successful parameters.

To add a benchmark, extend `Kind` and the `CATALOGUE` table in `src/benchmarks.rs`, add the formula to the `evaluate` match, and add a known point test. The catalogue test builds every entry at its default dimension, so a missing arm fails immediately.

## Performance notes

- Build with `--release` for measurements. Debug builds spend most of their time in bounds checks.
- Threads come from Rayon. `RAYON_NUM_THREADS=4 cargo run --release -- ...` fixes the pool size; the answer does not change, only the speed.
- The expensive part of a DE generation is the batch of trials, and the expensive part of a MOEA/D generation is the batch of children. Both are evaluated with `par_iter`, so a problem with a cheap evaluation will be dominated by the Rayon overhead. That is expected; the forecasting path is the target workload.
- A forecast evaluation fits one ridge model per fold. Reducing the fold count or the feature count is the effective way to speed up a search; the population size matters much less.

## Roadmap from the limits review

The cards name eight boundaries. This section turns each into a change, an order and a number that would say the change worked. The ordering rule is cheapest evidence first: a measurement that costs one fold and settles a question goes before a learner that costs an MCMC chain.

### Closed

**Embargo cannot be shorter than the label horizon.** A target that reaches `h` rows forward overlaps every row within `h`, so a training row at the edge of a fold saw the label of the row after it. `data::horizon_embargo` raises the gap, `forecast --horizon h` sets it, and a fold test asserts the gap equals the horizon. Until now the default of 1 leaked on any multi-row label.

**The search now prices itself (roadmap item 1).** `src/deflate.rs` records every distinct column set the forecast search scores, deduplicates the masks the engines revisit, and turns the winning score into `z`, the expected maximum of that many standard normals under the null, and a p-value. Three decisions are worth reading. Duplicates are one bet, not two, so the trial count counts distinct sets. Dependence between candidates is measured on the log fold profiles after the fold effect is removed, by cosine rather than correlation, because candidates that differ only by level are fully dependent and Pearson scores them as noise. The two corrections pull in opposite directions, so the gate quotes the larger of the two floors and says which is which. A synthetic 800 row panel with 12 features clears neither at 0.95: 1,179 distinct subsets, `z` 1.37, floor 3.30, budget 6 candidates, which is the seven-candidate rule of Bailey et al. (*Notices of the AMS* 61(5), 2014) showing up in this crate's own numbers.

**AUC intervals that hold where positives are scarce (item 4, interval half).** `uncertainty::delong_auc` computes the DeLong variance from the structural placements of every positive and negative and reports the bounds on the logit scale, so they cannot leave `(0, 1)`. On the shipped churn panel the DeLong reading is 0.867 `[0.858, 0.876]` with a standard error of 0.0046 against the bootstrap `[0.857, 0.876]`, and the card quotes the wider of the two.

**Every interval is now checked against a known truth (item 4b).** `uncertainty::bca` adds the bias and acceleration corrections, with the jackknife on the same placements DeLong uses, and `uncertainty::coverage` runs the simulation the roadmap demanded: 251 rows, 50 positives, a two normal world whose true area is 0.760 in closed form, nominal 95 percent, acceptance band 0.93 to 0.97. Bootstrap-percentile covers 0.938 at a mean width of 0.144, BCa 0.936 at 0.145 and DeLong 0.947 at 0.146, all inside the band at 2,000 trials.

The first version of this paragraph said the opposite, and the correction is the useful part. At 200 trials the same simulation put DeLong at 0.925, below the 0.930 floor, and the claim went into the card as a failure of the analytic interval. A share measured from 200 trials has a standard error near 0.015, which is wider than the gap; rerunning at 2,000 moved DeLong to 0.947. `uncertainty::wilson` now reports the interval on each measured share, `MethodCoverage::missed` refuses to call a miss resolved while that interval still reaches the band, and a test pins the arithmetic: separating a half-point gap at this level takes about eleven thousand trials. The lesson generalises past this panel. A coverage simulation is itself an estimate, and a card that prints one without its Monte Carlo error is quoting noise to two decimal places.

**The selection now has a distribution, not one path (item 2).** `forecast --cpcv` cuts the panel into contiguous groups, withholds `k` of them at a time, purges a gap on each side of every withheld run, and reads the distribution of paths and the probability of backtest overfitting. On the synthetic 800 row panel at `N = 6, k = 2` and a purge of 1, that is 15 splits and 5 paths: path spread 0.0027 in MSE, PBO 0.667, and a verdict that says selection lands in the better half on a third of the splits, which is a coin. The gate from item 1 and this audit agree, and they were built from different statistics.

**Class conditional conformal (item 5).** `uncertainty::mondrian` fits one threshold per label and refuses an `alpha` below `1 / n_c` for a class instead of printing a quantile it cannot estimate. At 90 percent on the churn panel the churn class covers 0.896 at a mean set of 1.90 and the stayed class 0.907 at 0.92, against a pooled 0.917 at 1.24. The pooled number was hiding that gap.

**The intervention question now has an estimate and a limit (items 7 to 10).** `causal` keeps the cross-fitted nuisances and reads them four ways: a doubly robust pseudo-outcome with an influence function interval, `dr_ate` 0.204 `[0.152, 0.257]` on a planted panel; an overlap weighted estimate that targets the population a decision can act on; a Crump trimmed estimate with its bound and retained row count; and an E-value of 2.44 with a 2.15 near-null bound, which states what unmeasured confounding would have to be, not that none exists. The policy value curve replaces Qini as the decision reading: the top decile is worth 0.338 against 0.204 for treating everyone. Qini stays as a descriptive ranking number, and it had a sign error until this round: the random baseline used the marginal treated-minus-control difference instead of the within-decile total, which reports a negative Qini for a correctly ranked model whenever the treated share varies by decile. A test now pins the sign.

**The labels now carry a ceiling and a resolution (items 16 and 18).** `src/audit` answers two questions a card that prints an accuracy has to answer, and neither needs a clean test set. `audit::confident` runs confident learning (Northcutt, Jiang and Chuang, *JAIR* 70, 2021) on the out-of-fold probabilities the fold loop already produces: a per-class threshold at the mean predicted probability of that class, rows that clear neither threshold left out of the confident joint, and the class totals then scaled back up to the labelled counts. `audit::power` turns a bank shape into the smallest difference it can resolve at 80 percent power, beside a three point floor fixed before any fit, using Hanley and McNeil's standard error for an AUC (*Radiology* 143, 1982) and the binomial one for a share.

On the shipped churn panel: 551 of 7,043 rows are confidently labelled against the model, 2,469 clear neither threshold, and the scaled estimate is 850 errors, 12.1 percent of the bank (12.8 percent of the churn labels, 11.8 percent of the stayed ones), so the ceiling against these labels is 0.879. The smallest resolvable AUC gain is 0.022 against the 0.030 floor, which the panel resolves. The detectors: `jargon` 10.0 percent noise and a 0.900 ceiling at 2,246 rows (28.7 percent of its positives), `legal` 4.9 percent and 0.951 at 2,259 rows; both sit just above the floor in resolution, at 0.035 and 0.031, so neither can demonstrate a three point gain at its own size. Emotion refuses the audit by name, because the scanner returns a reading with a tier and not a probability, and prints the resolution reading instead: 20 rows, leave-one-out 0.850, smallest resolvable gain 0.316, and about 2,224 rows to resolve the floor.

Four decisions are in the modules rather than in this file. Confident learning is only as good as the model behind it, and that has a known case: with every row scored the same the joint puts all rows in one class, the other class's noise reads one, and the ceiling collapses to the class share, which is the correct answer to the question asked and is now a test. The threshold is the mean of the probabilities it is compared against, so rows land on it by construction and one ulp of summation was enough to exclude a confident row; the comparison carries a one part in a trillion slack, pinned by a clean bank that must read zero noise and a ceiling of one. Where a large share of the bank is left out of the joint the scaling carries the estimate, and on churn that assumption is the difference between 12.1 percent and the 7.8 percent the contradiction count alone implies, which the card says in those words rather than printing the larger number alone. And the resolution figure is the independent bound; when a comparison already exists it is read paired, so the tree against the logistic is `+0.031 [+0.026, +0.036]` from `uncertainty::delong_pair` with the placements correlating at 0.85, not the 0.022 the independent form would have implied.

### Phase 1, make the selection defensible (no new models)

Closed. Item 1 and item 3 are the deflated gate, and item 2 is `forecast --cpcv` above: the gate prices how many bets were placed and the audit reads what happens when the split changes, so the selection is now criticised by two statistics that were built separately and agree on this panel. What is still not done, deliberately: the gate does not veto a run, because a veto at this trial count would refuse every search the crate can afford. It reports a candidate budget and a verdict, and the reader decides.

### Phase 2, uncertainty the sample size can carry

Closed, with one measured limitation.

4. The logit DeLong interval and item 4b, BCa plus the coverage simulation, both landed. The simulation's finding is that all three intervals hold at 50 positives once the trials are enough to see the difference, and that the first run was not: 200 trials reported DeLong at 0.925, 2,000 reported 0.947. The card quotes the measured coverage with its Monte Carlo interval rather than choosing an interval on a claim the simulation could not support.

5. Class conditional conformal with a refusal below `1 / n_c` landed as `uncertainty::mondrian`.

6. **Beta calibration landed as the default under a thousand rows.** `uncertainty::calibrate` fits `sigmoid(a ln p - b ln(1 - p) + c)`, three parameters, which handles over-confidence where isotonic would collapse in sample (Kull, Silva Filho and Flach, AISTATS 2017; Niculescu-Mizil and Caruana, ICML 2005, is the reason isotonic is not the default below about a thousand rows). On the churn panel the map is `a` 1.716, `b` -2.093, `c` +0.333, and the in-sample error falls to 0.006 from 0.075. The card says in sample, in bold terms, because that number is flattered by fitting and calibrating on the same rows. The delivered part of the item is the interval: ECE 0.075 `[0.069, 0.084]` and Brier with its own interval, both from resampling rows so the bins move with the sample. The honest held-out calibration comparison is open, and it needs a split the fit does not see, which is one extra fold and not a new method.

### Phase 3, the question the crate could not answer

Items 7, 8, 9, 9b and 10 landed: the doubly robust estimate, the E-value, the two overlap estimands, the policy value curve, and the window contract. What is open:

**Time zero is now a checked contract, not an assumption (item 9b).** `src/churn/contract.rs` asks the four questions a survival panel has to answer before a lift means anything: where time zero sits, whether month 0 can appear, how many rows are censored rather than counted as survivors, and how many months carry fewer than 30 rows at risk. On the shipped panel time zero is the join, month 1 is the first month at risk, 356 of 7,043 rows are censored at month 72, and no month falls under the at-risk floor. `churn check` recomputes the contract from the panel and the series independently and refuses when they disagree on the event count, so a panel edit that changes the window cannot pass silently. This closes what the roadmap called a data contract, with the limit stated in the card: the contract is written against month numbers, so a panel whose time zero is a campaign start has to shift and truncate before the check applies, and the repository has no such panel.

7b. **A causal forest is refused, deliberately.** At a few hundred rows the honest forest interval is wider than the decision it would support, so the tree ensemble stays a nuisance model behind the doubly robust score rather than a heterogeneity estimator.

### Phase 4, segmentation

11. **Bound every component's conditioning, not only its diagonal. Landed, at a cap the measurement chose, which is not the cap this item asked for.** The variance floor raises the diagonal, so an oblique component with a near-singular covariance still survives; the ratio of a component's longest axis to its shortest is now capped (`mixture::CONDITION_MAX`), with a Jacobi eigen-decomposition in `linalg` behind `condition_number` and `conditioning`. Two decisions came out of the measurement rather than the design. First, the bound is applied by `ship` to the model that ships and not inside the maximisation loop: clipping every intermediate covariance steers the search away from the shape the data supports, and the full covariance family reads 0.543 nats per entity held out with the shipped-model bound against -2.022 with the in-loop one at a cap of ten thousand, with identical placement agreement in both. Second, the cap is a trillion and not ten thousand. An eight column covariance from about two hundred rows carries an eigenvalue error of 0.08 against a longest axis of 1.4, so no ratio below about twenty can be separated from sampling error at all, and the sweep shows what a statistical-sounding cap costs: ten thousand and a million both hand the choice to the diagonal family at k = 5 with the full covariance fit at -1.668, a billion reads it at -0.095, a trillion at 0.543, unbounded at 0.609. A trillion is the edge of what a double-precision factorisation can invert, so it refuses a direction flat to twelve digits and nothing else. Shipped: full covariance at k = 4, held out 0.543 with a spread of 2.344 across folds, placement agreement 0.813, worst component 6,089, no component lifted, silhouette 0.222 against a 0.168 shuffled control. The honest summary is that a ratio cap cannot separate real near-collinearity from memorisation on this panel, so the card says that and prints the sweep instead of claiming a statistical bound it does not have.
12. **A two-part model for the zero mass. Closed as a gate with a measured acceptance, and the item's premise was wrong on this panel.** The item said clipping at 3 sd smears the spike. It does not: the clip never fires on either share, because a share with a boundary mass of `p` has its edge at `sqrt((1-p)/p)` in z, which is 1.22 for `repeat` and 0.68 for `concentrate`. The clip fires on ad volume, cadence, burstiness, spend, copy words and terms. What the pile costs is a group: a Gaussian can only imitate an atom with a component of almost no width, and then it reports a density where the data are a probability. `src/segment/gate.rs` fits, inside each chosen group, the chance a member sits on the edge and a normal for the members inside it whose mean moves with the other readings, which is the classical two-part model (Duan et al., *JETA* 22, 1983; Aitchison, *JRSS-B* 44, 1986, is the alternative the item offered and this panel did not need). The clip is nonetheless exempted on a gated column, because a share whose edge sits beyond the bound would have its edge folded into the interior and the atom would have no meaning.

The acceptance was rewritten because the one it asked for cannot be read. A likelihood with an atom and one without are densities against different measures: on an edge row the gate reports a probability and the Gaussian reports a density, and at this panel's spacing density times spacing exceeds one, which is a model credited with probability it cannot represent. Both sides are therefore scored as the probability of the observed value on the lattice the share lives on, the multiples of `1 / ads`, with the cell integrated rather than approximated, paired by fold. Shipped: `repeat` -0.891 against -1.000 for the Gaussian conditional law, Brier 0.098 against 0.116; `concentrate` -0.916 against -1.055, Brier 0.107 against 0.129. That is 0.248 nats per entity across the two shares, and the edge is called right on 84.1 and 81.2 percent of held-out rows against 60.1 and 64.1 percent for the panel rate. The groups read as shares now: `repeat` at 0 covers 100, 27.7, 0 and 100 percent of the four groups, with the inside mean printed beside it, and no clipped z is used to describe either reading.

Two things are deliberately not done. The gate is fitted to the partition rather than inside the expectation maximisation loop, because the mixed measure makes a likelihood comparison across the two families invalid and the partition is chosen on likelihood. That has since been measured rather than assumed, twice: the pattern mixture exists in `src/segment/pattern.rs`, and it is refused on the number both times. The first version imputed at a joint normal's conditional mean and scored -0.099 nats per entity against -0.988 on `repeat` and -0.142 against -0.915 on `concentrate`. The second gave the inside branch its own regression per group per gate, which is the estimator the first round's decomposition asked for, and it reads -1.165 against -0.988 and -0.915, 2.8 and 5.8 fold standard errors; a one-group reference reads -1.340 and -1.243, so neither the pooling nor the partition-as-chosen is the explanation, and the residuals say the per-group regression is a variance problem at 35 rows per group. It also draws a different partition, 135 of 251 held out rows move, so it is not a free replacement even if it had scored better. The prototype that put the gate in the loop as a six column marginal lost 0.64 nats per entity for a different reason, the gated columns carrying group separation; the pattern mixture keeps the dependence and loses on the inside branch instead. All of these readings are in the card.
13. **Concomitant gating on recency. Landed as a measured refusal, with the audit shipped and the weights left constant.** `src/segment/concomitant.rs` writes the mixing weights as `logit(pi_k(x))`, a multinomial logistic function of the descriptive columns, and leaves every density on behaviour (Dayton and Macready, *JASA* 83, 1988; Jacobs et al., *Neural Computation* 3, 1991). The gate is fitted on the soft responsibilities expectation maximisation hands it, by damped Fisher scoring with a ridge on every slope, alternating with the component step; the shape bound is applied once at the end rather than inside the loop, for the reason item 11 measured. The pre-registered model gates on recency alone, paired by fold on the same five folds the family choice used, each side starting from a plain fit with the same restarts. Shipped: constant weights 0.543 nats per entity, gated 0.544, gain +0.001 against a standard error of 0.005, worst component mean move 0.0008 sd. The wider set, recency, campaign span and test share, reads +0.135 against 0.208 with a fold to fold spread of 0.466, so it is unresolved rather than a gain and is printed beside the pre-registered model rather than instead of it.

The reason is visible before any fit and is the finding: recency explains 2.2 percent of its own spread across the four groups, and test share 0.6 percent, so neither has much group information left to carry. Span explains 75.0 percent, which is mechanical rather than informative, because span is close to ad volume and ad volume is already in every density. Two decisions were fixed before the numbers were read. The gate must add twice its own standard error, a rough rule stated as one, because five folds are all the noise estimate this panel offers and a one-standard error threshold would call the wider set a gain. And both halves of the acceptance are printed separately: the means steady check passes (0.0008 sd against a bound of 0.1), the likelihood check fails, and the card names which one failed. Because the gain is not there, the shipped model keeps constant weights, so `segment assign` still needs no covariates and the segments a reader has already seen do not move. A panel where recency did separate the groups would show it in this table rather than in a changed card.
14. **ICL beside BIC, and stability as a per-cluster flag. Landed, and the two halves gave opposite results: the per-cluster reading found a defect the aggregate had hidden, and ICL did not change a single choice.** ICL targets the partition and BIC targets the density (Biernacki, Celeux and Govaert, 2000; Baudry et al., *JCGS* 19(2), 2010), so `Mixture::icl` prints `BIC - 2 * sum log p` on every candidate and `segment info` shows the column beside BIC. On this grid the lowest ICL is the same near-saturated candidate as the lowest BIC, full covariance at k = 5, and the term that is meant to separate them is 0.3 nats across 251 entities, 0.001 per entity. The reason is measurable and it is the finding: a free covariance buys sharp posteriors, the chosen fit gives its own rows a mean winning posterior of 0.9994, so the ambiguity charge has almost nothing to charge. A criterion that is BIC plus a term that vanishes is BIC, and the card says that instead of implying the in-sample problem was repaired.
    The per-cluster Jaccard (Hennig, *CSDA* 52(1), 2007) did find something. Two of the four groups sit below the 0.6 floor: the 18 entity group at 0.266 mean (worst 0.079) and the 65 entity group at 0.589 (worst 0.352), against 0.626 and 0.893 for the other two, a mean of 0.593 across the partition. Both readings ship: the card names each group with its size, share, mean and worst Jaccard, the limits section says a flagged group is a region rather than a membership, `segment fit` prints how many hold, and the manifest carries the same line into `segment check`. Landed as a per-point audit rather than a sentence.** With five folds the standard error of 0.543 nats per entity is about 1.05, so no difference under a nat is resolvable, and the earlier instinct was to print the spread beside the headline. The nominal posterior: 250 of 251 rows above 0.9, one between 0.6 and 0.9, none below, mean margin 0.9988. ### Phase 5, small banks, cheapest first

16. **Audit the labels before buying more. Closed.** `audit::confident` now runs on churn and on both lexicon axes and prints the estimate, the ceiling and the rows left out of the joint. Confident learning estimates the joint distribution of noisy and true labels from out-of-fold predictions and ranks likely errors (Northcutt, Jiang and Chuang, *JAIR* 70, 2021). If 5 to 10 percent of the bank is mislabelled, that is the accuracy ceiling and a three-point gain sits inside it. Acceptance was the detectors, churn and emotion cards printing estimated label noise and a ceiling. Two of the three do; emotion refuses with the reason, since a tiered reading is not a probability and a ranking cannot be audited. The ceiling is an accuracy bound against the recorded labels, which is exactly why the ceiling is 0.879 on a panel whose AUC is 0.867: the two numbers are close enough that most of what is left on this bank is labels rather than behaviour.
17. **A learning curve that can see a ceiling. Landed, and it answers the question in one line.** Six points, each drawn on a split of its own: the id is salted (`#curve`) and partitioned again, so the curve's 100 percent point is an independent measurement of the same procedure rather than the headline scored on the folds that chose it. Four points on the scoring folds could not separate a ceiling from a blind design, and a curve measured on the rows it was selected on is not a measurement (Viering and Loog, arXiv:2103.10948, 2023; Cortes et al., NeurIPS 1993). Shipped, on 528 to 5,282 training rows: AUC 0.866, 0.864, 0.867, 0.867, 0.868, 0.867 with fold standard errors of 0.002 to 0.003, and accuracy 0.793, 0.781, 0.787, 0.778, 0.790, 0.790. The last-doubling gain is -0.12 AUC points. The ceiling comparison runs on accuracy, because the label audit's ceiling is an accuracy and comparing it with an area would be a scale error dressed as a finding: 0.790 against 0.879, a gap of 0.089 with a standard error of 0.005, the wider of the fold spread and the binomial error on the 7,043 test rows. The verdict is that the bank is below the ceiling but flat, so the remaining gap is the features or the operator, not the row count. The inverse-power fit the acceptance asked for is printed beside it: no rising power law passes through the accuracy column, so the reported limit is the last measured point, and the card says exactly that rather than quoting an extrapolation the data do not support. `churn fit` prints the curve and the verdict in two lines.
18. **A detectable delta on every card. Closed.** Hanley and McNeil's standard error is 0.025 at 251 balanced rows and 0.036 at 20 percent positives (Hanley and McNeil, *Radiology* 143, 1982), so a claimed 0.03 gain is about one standard error. Pre-registering the minimum worthwhile delta and printing the smallest gain the sample can resolve at 80 percent power is what `audit::power` does, on the AUC scale for forecast and churn and on the accuracy scale for emotion and the detectors. The three point floor is the one the review used, and it is now a constant in `AuditConfig` rather than a sentence in a card.
19. **One transfer move.** A frozen subword embedding file with a hashed linear head is pure Rust and covers out-of-vocabulary words (Bojanowski et al., *TACL* 5, 2017; Weinberger et al., 2009). SetFit's few-shot result is the prior worth testing (Tunstall et al., 2022). Refuse self-training on twenty transcripts: the teacher is the weak link and confirmation bias is the known failure (Oliver et al., NeurIPS 2018).
20. **The encoder stays a fixture.** Do not claim it as a text model. The tabular question is already answered on the churn panel, trees 0.898 against logistic 0.867, which is the direction Grinsztajn et al. report (*NeurIPS* 2022).

### Phase 6, monitoring that is honest about labels

21. **A drift gate calibrated to the sample. Landed, and the first measurement changed the null twice.** The folklore bands on the index are a property of the sample, not of the statistic: the measured 95th percentile is 0.059 at a thousand rows a side and 0.338 at a hundred (Yurdakul and Naranjo, *Journal of Risk Model Validation*, 2020; Siddiqi, 2006, is where 0.1 and 0.25 come from). `src/monitor/gate.rs` scores each feature against a null generated at the row counts the reading was taken at. The index null is its delta-method law: the statistic is a quadratic form in zero-mean normal differences with `bins - 1` degrees of freedom and scale `sum (1 - p_i) * (1 / n + 1 / m)`, drawn rather than tabulated. Cramer-von Mises is added because a sum over bins cannot see a move the bins merge, and its null is the asymptotic law built from a Karhunen-Loeve expansion of the Brownian bridge, with a test pinning the 95th percentile at the tabulated 0.461 (Anderson and Darling, *Annals of Mathematical Statistics* 23, 1952). The two per-feature readings are combined with a factor of two for the double test and applied to Benjamini and Hochberg across features (*JRSS-B* 57, 1995); a kernel two-sample reading on the whole standardised vector is printed beside them with its median bandwidth and its permutation count (Gretton et al., *JMLR* 13, 2012). `churn monitor` prints the calibrated threshold, the Cramer-von Mises critical value, the per-feature table and the joint p-value, and `--threshold` still fixes a band in index units when a caller insists, with the report saying the calibration was overridden.

    The numbers are the acceptance. At 7,043 rows a side the calibrated 5 percent threshold reads 0.0046 to 0.0049 per feature, so the folklore 0.1 band is twenty times a 5 percent test here and would have been reported as a permanent alarm at a hundred rows. On 200 stationary splits of a thousand rows a side the gate fired 11 times, 5.5 percent, Wilson [3.0, 9.7], against the five percent target; the sharper reading is that both component p-values are calibrated in their own tails, 0.048 for the index and 0.049 for Cramer-von Mises at the 5 percent point over 800 draws, which is what two hundred splits cannot resolve. The shipped demo is two commands: the panel against itself reads stable with every p at 1.000, and a copy with `monthly` raised 25 percent alarms on `monthly` alone (index 0.747, Cramer-von Mises 93.2, joint p 0.050) with the other seven features untouched.

    Two defects, both caught by the stationary test rather than by reading the code. The first null conditioned on the reference shares and drew only the current sample, which understates the law by a factor of about two because both samples move; on that null a stationary backfill fired on 123 of 200 splits, 61.5 percent, and the fix was to derive the law from both row counts. And `mmd_rows: 0`, written to switch the joint reading off, was clamped to two rows, so the disabled test ran a two-row permutation at whatever rate the tie-breaking gave; a cap below two is now off, and a test pins it.

22. **A matured-cohort table. Landed, and the refusal is the finding.** `src/churn/cohort.rs` splits the panel into tenure bands, which with a fixed snapshot is the same as a registration vintage, and marks a band mature for the twelve month horizon when its lower edge reaches twelve months, so every row in it has been watched long enough for the label to occur (Chapelle, *KDD* 2014, on the selection a fixed window creates). The two young bands, 0-6 and 7-12 months, are printed with their rate, their censored count and the reason their readings are missing rather than with a corrected number. Shipped: 4,974 of 7,043 rows are mature and carry the readings, with the recorded rate falling from 0.533 in the youngest band to 0.066 beyond five years, which is mostly the length of the observation rather than a change in behaviour. Over the mature bands the held-out AUC reads 0.839, 0.864, 0.829, 0.844 and 0.852, pooled 0.859 against 0.867 over the whole panel, so the censored rows were not carrying the score; the expected calibration error falls from 0.092 to 0.045 as the base rate falls; the pooled conformal set covers 0.928, 0.936, 0.896, 0.893 and 0.938 of each band against a nominal 0.90, which is the one reading that moves the wrong way at the low base rate; and the shipped model beats the tenure-only reference within every band, +0.090 to +0.128 with every interval above zero. That paired column is the only comparison the table allows: each band is measured against its own base rate, so no two bands are compared with each other, and a snapshot records that a customer churned rather than when, so no band here is a twelve month rate.

    One defect, and it is the kind that survives a review because the number looks plausible: `conformal_set` returns the negative label first, so the first version of the coverage column read 0.443 on a band whose churn rate is 0.287 and fell monotonically with maturity. The column was measuring the wrong membership, and the give-away was that its pattern tracked the base rate rather than the nominal level.

23. **An audit trail, not a pointer. Landed, with the two ways it can mislead stated in the code.** A version now carries the SHA-256 of the artifact bytes, the SHA-256 of the panel it was fitted on, the rows and the window range, the seed (absent, which is a claim that the fit draws nothing and one `churn check` tests), the readings the card claims, and the parent version. SHA-256 is written out in `src/digest.rs` with the published vectors as tests, because FNV-1a, which the manifests use, detects an accident and not an edit. `Registry::verify` recomputes the digest of the stored bytes, and `rollback` refuses to restore a version that fails it; publish and rollback each append a line to `history.jsonl`, which is never rewritten, so the sequence of decisions survives the pointer moving. `churn publish` builds the trail from the artifact and the panel beside it, and `churn versions` prints every version with its state, its range, its readings and the log. That is the model-card and SR 11-7 minimum. What it still is not: a signature. The digest says the bytes are the bytes recorded, not who recorded them, and the registry is a local directory, so an attacker with write access can rewrite both the artifact and its record. The card-level claim is tamper evidence, not authenticity.
24. **A sequential reading, and the refusals that keep it honest. Landed, and the refusal is the result.** `src/monitor/sequential/` implements ADWIN (Bifet and Gavalda, *SDM* 2007) over an exponential bucket window, with two bounds: Hoeffding on the known range `[0, 1]` and the empirical Bernstein bound on the pooled variance of the two halves (Maurer and Pontil, *Machine Learning* 75, 2009). The level is calibrated, not defaulted. Measured at a batch of 200 labels at 2 percent: 0 of 100 stationary streams of 1,000 batches raise a cut at any level from 0.001 to 0.5, the upper end of that share is 0.037, and the budget of one stream in twenty in error is therefore held twice over, by the level's own promise and by the count. That gives `delta` = 0.05, and the grid is printed with each point's delay so the trade is visible rather than asserted. Throughput: a tripling of a 2 percent rate is caught after a median of 1,623 batches at that level, against 241 rows, a batch and a fifth, for a fixed-sample test of the same shift, 1,351 times the data, which is the price of a bound that has to hold at every stopping time.

    On the panel's own series, 72 tenure months, the bound resolves 0.537 against a window mean of 0.007, seventy-four times the level, so no cut is possible and the card says the absence of a cut is arithmetic rather than stability; the shuffle null is refused as evidence in the same sentence, because a window that cannot cut has no null to compare with. The per-event refusal is arithmetic rather than taste: one label at 2 percent carries a relative standard error of 700 percent, a batch of 200 carries 49 percent, and the fixed-sample floor for a 25 percent shift is 64 batches. Nothing per-event is offered. Two bounds ship because the range bound was measured blind: on a step from 0.02 to 0.06 over 4,000 batches the variance bound cuts and Hoeffding does not, which is what using `[0, 1]` as the range of a rare rate costs. `churn stream` prints the calibration, the reading, the shuffle, the cost comparison and both refusals; the card carries the same block from the artifact.

### What this roadmap does not close

- Unmeasured confounding stays unmeasured. The E-value quantifies how strong it would have to be; it does not remove it.
- Recency stays out of the densities, and on this panel out of the mixing weights as well: the audit closes the second question with a number (+0.001 nats per entity against a standard error of 0.005) instead of leaving it open. A second panel where recency separates the groups would change that reading and would show up in the table before it changed a card.
- Twenty transcripts stay twenty transcripts. No estimator turns them into a general claim; the only honest moves are transfer and more labels.
- The segment family choice remains one panel's answer. A second panel is the test, and there is not one in the repository.

### What the last three rounds bought, and what they point at

The items the review opened are now closed, the last of them on a measured refusal rather than a gain: the horizon embargo, the deflated selection gate, the CPCV audit, the logit DeLong interval, BCa with the coverage simulation, class conditional conformal, beta calibration with intervaled errors, the doubly robust and E-value causal reading, the window contract, the conditioning bound, the zero-mass gate, ICL with the per-cluster Jaccard, the per-point sharpness audit, concomitant gating read rather than assumed, the pattern mixture, the size-aware drift gate, the matured-cohort table, the six point learning curve with its ceiling comparison, the registry audit trail, the pattern-specific conditional, and the pooling of its inside slopes. The next items are the ones the new numbers point at.

1. **The pattern-specific conditional inside the loop, landed on a refusal that names the next move.** The inside branch now has its own conditional law: each group's gated reading is regressed on the six readings the score conditions on, weighted least squares on the rows that show a value, with its own residual variance and the measured residual correlation between the two shares carried instead of assuming conditional independence (0.63 on this panel, where the assumption would have been false). The stored covariance is completed from those pieces so that conditioning it returns the regression exactly, and a test pins that. The reading moved the wrong way: the loop model now reads -1.165 nats per entity against -0.988 and -0.915 for the gate fitted to the partition, 2.8 and 5.8 fold standard errors, against -0.099 and -0.142 for the version that imputed at a joint normal's conditional mean. The measurement also says why, and it is not the regression. The loop model fits its inside residual on fewer rows per group, 37.8 and 35.2 against 50.6 and 44.6, and gets a tighter residual in sample, 0.187 and 0.422 against 0.285 and 0.460, while predicting worse out of sample; it is sharper in the block the score conditions on, 0.978 against 0.922; and a one-group reference, where the conditional is pooled rather than per group, reads -1.340 and -1.243, so grouping does buy something and the shortfall is neither the regression nor the pooling. Six coefficients per group on thirty-five rows is a variance problem, and the answer the numbers support is partial pooling, which is the next item rather than a claim made here. The partition the loop draws now agrees with the shipped one on 46.2 percent of held-out rows, against 58.1 before, which is the second reason the artifact stays where it is.
2. **Partial pooling of the per-group conditional. Landed, and it closed part of the gap and named the rest.** Each group's slope is now a precision weighted average of its own estimate and the slope fitted to the whole panel. The weight is empirical Bayes with the between-group spread of each coefficient measured net of the sampling variance that spread is contaminated by, so a coefficient whose groups differ by less than their own errors is pooled and one that does not is left alone. The pooled weight is reported per share, and the three settings are scored on one partition: three independent fits land in different places, which is measured and printed rather than argued, so a single maximisation step on the shipped model's own responsibilities separates the estimator from the grouping. `repeat` reads -1.134 with no pooling, -1.118 at the shipped weight and -1.083 fully pooled; `concentrate` reads -1.144, -1.087 and -1.027; the one-group reference is -1.340 and -1.243. The gap against the gate fitted to the partition falls from 0.177 and 0.251 nats to 0.130 and 0.173, so pooling buys 0.047 and 0.078 and does not close the question. The weight the panel asked for is 0.92 on one share, where the between-group spread is 0.025, and 0.78 on the other, where it is 0.144. Full pooling is +0.003 nats better on the first (se 0.003) and +0.061 on the second (se 0.035), which is one and 1.7 standard errors: not separated, so the adaptive weight ships, because taking the extreme because it won by a fraction on the same folds is the selection the deflated gate exists to refuse. What pooling did fix is the inversion the previous round measured: the loop's inside residual is now 0.297 against the gate's 0.285 and 0.463 against 0.460, so it is no longer the tighter in-sample residual of a model that predicts worse. The remaining shortfall is the partition, and the card says so with the numbers beside it.
3. **The same weighting on the gate side, so the comparison stops favouring the gate.** The two-part gate fits its own slope per group on 50.6 and 44.6 rows; the loop model, after pooling, effectively fits on the whole panel's inside rows. The comparison in the card therefore gives the gate the advantage of more rows while leaving its slope at the noisiest estimate in the repository. `gate::fit_inside` already returns the standard errors the shrinkage needs, so the acceptance is measurable on the same two numbers: the gate's held-out -0.988 and -0.915 should not move against the loop by pooling alone, and if they improve by two standard errors the loop model's gap is being measured against a weaker opponent than the one it will face. A hierarchical bootstrap, resampling rows and re-estimating the weight, would say whether a weight of one is excluded; a one-interval that contains it means the panel is not distinguishing pooled from partially pooled at all, which is a stronger statement than the current "not separated by two standard errors on the score". This is the last place in the segmentation where a number is printed without its own error.
5. **One transfer move on the twenty transcripts (item 19).** The emotion bank resolves a 0.316 AUC difference and refuses a label audit; the only remaining test that does not need new labels is a frozen subword embedding trained on the unlabelled corpus, with the twenty rows scoring on the same folds. Three defects surfaced in the pooling round, and the first is the reason the round took as long as it did. The expectation maximisation loop kept its own starting point as a candidate, and the starting point carries components built from a k-means partition with no regression readings at all; on a run whose first maximisation step happened to score lower, the fit shipped zeroed slopes beside a real partition and reported them as the model. The second: the three-way pooling comparison was first run as three independent fits, and the two extremes placed only 39 percent of the held rows in the same group, so most of the difference being read as the estimator was the partition. The table is now computed on one partition and the refit-apart share is printed beside it, which is the honest version of the same number. The third is a reading that looked like a result and was an averaging error: the printed pooling weight was the last fold's fit rather than the mean over folds, so a fold-averaged 0.92 would have printed as 1.00.

Three more defects surfaced in the round before, all of the arithmetic kind that a plausible-looking number hides. The mirror that symmetrises the free block copied raw sums into the lower triangle, which a stored covariance would have carried as a zero half; the test that the no-edge case reduces to the standard step caught it. The one-group reference clamped a log score with a floor meant for a probability, which turned every row into -27.631 and would have printed the pooled model twenty-seven nats behind for an arithmetic reason. And the row counts that compare the two models were first accumulated as weighted totals on one side and row counts on the other, which made the gate look like it had twice the sample it had.

Four defects surfaced while landing the earlier rounds, and every one was found by writing the same number down twice and comparing. The gate's first dependence correction called an entire synthetic search one bet, because Pearson on near-parallel fold profiles divides by rounding error. Qini had the wrong random baseline and reported a negative coefficient for a correctly ranked model. The calibration note formatted the fitted error from full precision while the table beside it formatted a rounded value, so one number printed as 0.006 and 0.007 in the same section; `num::round4` is now the single definition and `check_docs.py` also fails a Rust string continuation that glues two words together, which is how the window paragraph shipped as `eventcount` and `month72`. And the coverage simulation reported a DeLong failure that was its own sampling noise, which is the defect that matters most because the tool was built to catch exactly that in other people's claims.

The shape is the same in all four: a number was printed without the precision it was measured to. That is the argument for the contract these cards now follow. A printed number is a testable claim, and the test is that the quantity appears the same way everywhere, carries its interval, and is not asked to settle a difference smaller than its own error.

Two more surfaced in the last round. Five modules carried their own `commas`, so "1,355,000" and "1355000" could have appeared in one card; the single definition now lives in `num` with `round4`. And the conditioning bound's first cap was a round number chosen before the sweep existed, which would have shipped a different segmentation for no measured reason.

The gating audit produced a third of the same shape, and it is the sharpest illustration yet. The gated score used the gate's logits where it needed its log probabilities, so every row carried an extra `ln 4` of 1.386 nats. On this panel that would have been reported as a gain of 1.386 nats per entity against a standard error of 0.005, which is the most significant result the repository would ever have printed, and it was arithmetic on the normalising constant. A test asserting that a uniform gate scores exactly like the mixture it wraps caught it before the first card was written. The rule the repository keeps rediscovering: every score needs a known case it must reproduce, and a model that nests a simpler one has that case built in.

The pattern mixture produced the fourth and the most expensive. Its maximisation step added both orders of the conditional covariance to one upper-triangle cell of the second moment, which doubles the off diagonal, makes the weighted average indefinite, and fails the positive-definite check. The failure code returned an empty component list, which the loop read as convergence, so every fit stopped after a single step and reported the likelihood of a one-step model. The comparison read the pattern mixture 0.32 and 0.23 nats per entity worse than the gate, on five folds, at seven and five standard errors, which is exactly the shape of a decisive result. Two things exposed it: the fit's own iteration count was one, and a panel drawn from the model showed the pattern mixture losing to the two-part gate on its own data, which is impossible for a correctly specified model. The fixed version is 0.099 and 0.142 behind, and the first of those is 1.6 standard errors. Both checks are now tests: the fit must run until its likelihood settles, and the model must not lose on its own data.

The monitoring round added four more of the same family, and three of them were in the statistic rather than in its printing. The drift null was conditioned on the wrong side: it drew from the reference shares at the combined row count, which understated the variance when the two panels differ in size, and the stationary gate fired 11 times in 200 splits only after the null was rebuilt from each side's own counts. The kernel two-sample reading returned a p-value of 1.0 whenever a group had two rows, because the statistic is invariant when the kernel matrix is degenerate and the permutation test then had nothing to permute. The conformal class order was read from the model's class vector rather than from the label, so the positive class's threshold was applied to the negative class, which a class conditional coverage of 0.896 at a nominal 0.90 nearly hid. And the window paragraph was duplicated in the card, which is how the same sentence appeared with two different row counts.

This round added two more, and both were caught by printing the value rather than by a test. The learning curve's first accuracy standard error was the fold spread alone, 0.002, while the binomial error on 7,043 test rows is 0.005, so the ceiling comparison would have been quoted at less than half its true width; the bar for every verdict is now the wider of the two. And the registry table printed `published` as `2026-11-1` because it was truncated to nine characters to fit a column, while the publish trail labelled a nominal 90 percent interval as `at 10 percent` because it printed alpha where it meant one minus alpha. Both are the calibration-note failure again: a number displayed in a form that says something the measurement did not, which is why the table and the trail now print the reading and not a rounded view of it.
